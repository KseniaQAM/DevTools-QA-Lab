## BR-001. Однократное нажатие на «Войти» формирует два запроса на авторизацию

**Предусловия:**
1. Открыта страница входа.
2. Пользователь не авторизован.

**Шаги воспроизведения:**
1. В поле «Логин» ввести `anna.qa`.
2. В поле «Пароль» ввести `QA_Lab_2026!`.
3. Открыть DevTools, вкладку Network.
4. Нажать кнопку «Войти».

**Фактический результат:**

Однократное нажатие на кнопку «Войти» формирует два запроса на авторизацию.

**Ожидаемый результат:**

Одно нажатие на кнопку «Войти» формирует один запрос входа.

**Severity:** Minor — дефект не сказывается на пользовательском пути, функции сайта продолжают быть доступными.

**Priority:** Low.

**Вложения:**
- https://joxi.ru/Ay66nRgtG769yr
- https://joxi.ru/27EEWVyHEGqL0r

**Технический комментарий:**

В DevTools во вкладке Network в запросах login были обнаружены разные инициаторы. В Sources было обнаружено, что первый запрос формирует обработчик нажатия на кнопку (строка 43), второй запрос формируется отправкой формы через обработчик submit.

Скриншоты:
- https://joxi.ru/r899dV7tnwgK4m
- https://joxi.ru/ANBBdvoHxeG1vA
- https://joxi.ru/rJjjQvoteXdQMr

## BR-002. При нажатии на «Добавить 1 шт.» в корзину добавляется два товара

**Предусловия:**
1. Пользователь авторизован.
2. В корзине отсутствуют товары.

**Шаги воспроизведения:**
1. В каталоге выбрать товар «Термокружка север».
2. Нажать на кнопку «Добавить 1 шт.».
3. Открыть корзину и обратить внимание на количество товаров в ней.

**Фактический результат:**

При однократном нажатии на кнопку «Добавить 1 шт.» в корзину добавляется два товара.

**Ожидаемый результат:**

В корзину добавлена одна единица выбранного товара. Счётчик корзины соответствует добавленному товару.

**Severity:** Critical — дефект мешает пользовательскому пути, некорректно работает важная функция добавления товара в корзину. Вследствие этого в корзине отображаются некорректные количество и стоимость товара.

**Priority:** High — дефект необходимо устранить как можно быстрее.

**Вложения:**
- https://joxi.ru/AnNNxjnU0DdjnA

**Технический комментарий:**

В DevTools во вкладке Network в запросе items было передано количество товара 2. В Initiator можно увидеть, что запрос был инициирован 52-й строкой JS-кода. В Sources в 52-й строке можно увидеть формирование POST-запроса с количеством товара в размере 2 штук.

Скриншоты Payload, Response POST и GET-запросов, а также вкладок Initiator и Sources:
- https://joxi.ru/AkEEyjRH1dayem — Payload
- https://joxi.ru/21JJ9VOUVE18ZA — Response POST
- https://joxi.ru/27EEWVyHEGqogr — Response GET
- https://joxi.ru/r899dV7tnwg45m — Initiator
- https://joxi.ru/ANBBdvoHxeGBoA — Sources, строка 52

## BR-003. Поле «Телефон» возвращает старое значение после сохранения новых данных профиля

**Предусловия:**
1. Пользователь авторизован.
2. Открыт раздел «Профиль».

**Шаги воспроизведения:**
1. Изменить поле «Имя» на «Анна Морозова QA».
2. Изменить поле «Электронная почта» на `qa.anna@example.com`.
3. Изменить поле «Телефон» на `+7 900 222-33-44`.
4. Нажать кнопку «Сохранить изменения».

**Фактический результат:**

После сообщения об успешном сохранении поле «Телефон» возвращает старое значение.

**Ожидаемый результат:**

При корректных значениях изменения сохраняются; интерфейс подтверждает успешное сохранение и показывает новые значения после повторного получения профиля.

**Severity:** Major — дефект мешает пользовательскому пути, но остальная функция редактирования профиля доступна.

**Priority:** Medium — дефект исправить можно в плановом порядке.

**Вложения:**
- https://joxi.ru/Ay66nRgtG76wzr

**Технический комментарий:**

В DevTools во вкладке Network в запросе profile к `http://localhost:8000/api/profile` в Payload были переданы новые значения. Response того же запроса содержит старое значение для ключа `phone`.

При повторном получении профиля в запросе profile к `http://localhost:8000/api/profile` Response содержит старое значение ключа `phone`.

Скриншоты:
- https://joxi.ru/27EEWVyHEGqN1r — Payload
- https://joxi.ru/r899dV7tnwgMRm — Response PUT
- https://joxi.ru/rJjjQvoteXdnLr — Response GET

## BR-004. Интерфейс не выводит сводку при нажатии на «Показать сводку» в разделе «Настройки»

**Предусловия:**
1. Пользователь авторизован.
2. Открыт раздел «Настройки».

**Шаги воспроизведения:**
1. Нажать на кнопку «Показать сводку».
2. Обратить внимание, что в интерфейсе не появляется короткая сводка по текущим записям.

**Фактический результат:**

После нажатия на кнопку «Показать сводку» интерфейс не выводит короткую сводку по текущим записям.

**Ожидаемый результат:**

Расчёт завершается без необработанных ошибок. Итог сводки отображается в интерфейсе.

**Severity:** Major — дефект мешает пользовательскому пути, но остальные функции остаются доступными.

**Priority:** Medium — дефект исправить можно в плановом порядке.

**Вложения:** отсутствуют.

**Технический комментарий:**

В DevTools во вкладке Console была обнаружена ошибка:

`ReferenceError: Uncaught ReferenceError: summaryState is not defined`

В Sources в строке 97, столбце 79 было обнаружено, что код обращается к `summaryState`, но такой переменной в Sources нет.

Скриншот:
- https://joxi.ru/2pnnzQxHVlEGdr
