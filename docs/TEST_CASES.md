# Тест-кейсы

**Пользовательские сценарии и ожидаемое поведение по требованиям**

| Параметр | Значение |
|---|---|
| Идентификатор | DQL-DOC-05 |
| Версия | 2.0 |


## TC-01. Успешный вход с корректными учётными данными

**Требования:** REQ-AUTH-01, REQ-AUTH-02, REQ-AUTH-06

**Предусловие:** Стенд запущен; открыта страница входа; пользователь не авторизован.

**Шаги воспроизведения:**
1. Ввести логин `anna.qa`.
2. Ввести пароль `QA_Lab_2026!`.
3. Нажать «Войти».

**Ожидаемый результат:**
- После отправки данных открывается каталог.
- Приложение отображает авторизованное состояние.
- Одно нажатие формирует один запрос входа.

**Статус:** Failed

## TC-02. Отказ во входе с неверным паролем

**Требования:** REQ-AUTH-03

**Предусловие:** Открыта страница входа; пользователь не авторизован.

**Шаги воспроизведения:**
1. Ввести логин `anna.qa`.
2. Ввести неверный пароль `WrongPass!`.
3. Нажать «Войти».

**Ожидаемый результат:**
- Вход не выполняется.
- Пользователь остаётся на странице входа и видит сообщение об отказе.
- Авторизованная сессия не создаётся.

**Статус:** Passed

## TC-03. Сохранение сессии при навигации и обновлении страницы

**Требования:** REQ-AUTH-04

**Предусловие:** Пользователь авторизован.

**Шаги воспроизведения:**
1. Перейти из каталога в профиль.
2. Вернуться в каталог.
3. Обновить страницу каталога.

**Ожидаемый результат:**
- Защищённые разделы доступны без повторного входа.
- После обновления пользователь остаётся в авторизованном состоянии.

**Статус:** Passed

## TC-04. Завершение сессии после выхода

**Требования:** REQ-AUTH-05

**Предусловие:** Пользователь авторизован; открыта любая защищённая страница.

**Шаги воспроизведения:**
1. Нажать «Выйти».
2. Повторно открыть адрес защищённого раздела.

**Ожидаемый результат:**
- Пользователь выходит из приложения.
- Защищённый раздел не предоставляет доступ к данным и требует повторного входа.

**Статус:** Passed

## TC-05. Отображение каталога

**Требования:** REQ-CAT-01

**Предусловие:** Пользователь авторизован.

**Шаги воспроизведения:**
1. Открыть раздел «Каталог».

**Ожидаемый результат:**
- Отображаются три товара.
- Для каждого указаны название, категория, краткое описание и цена.

**Статус:** Passed

## TC-06. Добавление одной единицы товара в корзину

**Требования:** REQ-CAT-02, REQ-CART-01—03

**Предусловие:** Пользователь авторизован; корзина пуста.

**Шаги воспроизведения:**
1. В каталоге выбрать товар «Термокружка Север».
2. Нажать действие добавления товара в корзину один раз.
3. Открыть корзину.

**Ожидаемый результат:**
- В корзину добавлена одна единица выбранного товара.
- Счётчик и содержимое корзины соответствуют добавленному товару.

**Статус:** Failed

## TC-07. Сохранение содержимого корзины при переходах

**Требования:** REQ-CART-03, REQ-CART-05

**Предусловие:** Пользователь авторизован; в корзину добавлена одна единица товара.

**Шаги воспроизведения:**
1. Открыть каталог.
2. Перейти в профиль.
3. Вернуться в корзину.

**Ожидаемый результат:**
- Содержимое корзины сохраняется при переходе между разделами в рамках активного сеанса.
- Количество и сумма соответствуют содержимому корзины.

**Статус:** Passed

## TC-08. Удаление товара из корзины

**Требования:** REQ-CART-03, REQ-CART-04

**Предусловие:** Пользователь авторизован; в корзине находится одна единица товара.

**Шаги воспроизведения:**
1. Открыть корзину.
2. Нажать «Удалить» у строки товара.

**Ожидаемый результат:**
- Строка товара удалена, итоговая сумма пересчитана.
- Если корзина пуста, отображается предусмотренное пустое состояние.

**Статус:** Passed

## TC-11. Проверка обязательности полей профиля

**Требования:** REQ-PROF-02

**Предусловие:** Пользователь авторизован; открыт профиль; исходные данные сохранены для последующего восстановления.

**Шаги воспроизведения:**
1. Очистить поле «Имя», оставив остальные поля заполненными.
2. Попытаться сохранить профиль.
3. Повторить проверку отдельно для поля электронной почты.
4. Повторить проверку отдельно для поля телефона.

**Ожидаемый результат:**
- Каждое из трёх полей является обязательным.
- При незаполненном поле изменения не сохраняются.
- Точный текст сообщения требованиями не установлен.

**Статус:** Passed

## TC-12. Фильтрация записей справочника по категории

**Требования:** REQ-SET-01, REQ-SET-02

**Предусловие:** Пользователь авторизован; открыт раздел «Настройки и данные».

**Шаги воспроизведения:**
1. Выбрать категорию «Оплата».
2. Применить фильтр.
3. Выбрать вариант «Все».
4. Применить фильтр повторно.

**Ожидаемый результат:**
- При выборе категории отображаются записи выбранной категории.
- При выборе «Все» отображаются все записи.
- Если совпадений нет, показано явное пустое состояние.

**Статус:** Passed

## TC-13. Публикация и обновление справочника

**Требования:** REQ-SET-03—05

**Предусловие:** Пользователь авторизован; открыт раздел «Настройки и данные»; зафиксирована исходная версия.

**Шаги воспроизведения:**
1. Зафиксировать текущую версию справочника.
2. Выполнить команду «Опубликовать обновление».
3. Выполнить команду «Обновить данные».

**Ожидаемый результат:**
- Публикация подтверждается, версия увеличивается.
- После обновления и повторного открытия отображаются актуальная опубликованная версия и соответствующие записи.

**Статус:** Passed

## TC-14. Формирование сводки

## TC-15. Возврат стенда к исходным данным

**Требования:** REQ-GEN-04

**Предусловие:** Стенд запущен; выполнены изменения в одном или нескольких разделах.

**Шаги воспроизведения:**
1. Нажать «Сбросить стенд».
2. Подтвердить сброс, если появится запрос подтверждения.
3. Повторно войти с исходными тестовыми данными.
4. Проверить корзину, профиль и справочник.

**Ожидаемый результат:**
- Стенд возвращён к исходному состоянию: корзина пуста, профиль и справочник содержат исходные данные.
- Для дальнейшего прогона можно использовать те же тестовые данные.

**Статус:** Passed
