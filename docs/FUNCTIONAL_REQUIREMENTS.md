# Функциональные требования

**Спецификация ожидаемого поведения DevTools QA Lab**

| Параметр | Значение |
|---|---|
| Идентификатор | DQL-DOC-02 |
| Версия | 2.0 |

## Назначение документа

Документ является источником ожидаемого поведения для тест-кейсов, чек-листа и оценки результатов.

Фактическая реализация не заменяет требования. Если требование не задаёт конкретное значение или технический механизм, тестировщик не должен придумывать его.

---

## 1. Общие требования

| ID | Требование |
|---|---|
| REQ-GEN-01 | Приложение доступно локально по адресу `http://localhost:8000` после запуска включённого в комплект сервера. |
| REQ-GEN-02 | Интерфейс содержит отдельные разделы: авторизация, каталог, корзина, профиль, настройки и данные. |
| REQ-GEN-03 | После успешного входа пользователь может переходить между защищёнными разделами. |
| REQ-GEN-04 | Демо-данные восстанавливаются кнопкой сброса или перезапуском сервера. |
| REQ-GEN-05 | Все суммы отображаются в рублях; тестовые данные не являются реальными персональными данными. |

## 2. Авторизация и сессия

| ID | Требование |
|---|---|
| REQ-AUTH-01 | Регистрация отсутствует. Для входа используются выданные тестовые логин и пароль. |
| REQ-AUTH-02 | При корректных данных приложение открывает каталог и отображает авторизованное состояние. |
| REQ-AUTH-03 | При неверных данных вход не выполняется; пользователь видит понятное сообщение, авторизованная сессия не создаётся. |
| REQ-AUTH-04 | Сессия сохраняется при переходе между разделами и обновлении страницы до выхода или истечения срока действия. |
| REQ-AUTH-05 | После выхода сессия завершается, защищённые разделы требуют повторного входа. |
| REQ-AUTH-06 | Одно нажатие пользователем кнопки «Войти» формирует один запрос входа. |

## 3. Каталог и корзина

| ID | Требование |
|---|---|
| REQ-CAT-01 | Каталог показывает три товара: название, категорию, краткое описание и цену. |
| REQ-CAT-02 | Для каждого товара доступно добавление одной единицы в корзину. |
| REQ-CART-01 | При добавлении товара сервер получает идентификатор выбранного товара и количество 1; операция завершается успешно. |
| REQ-CART-02 | После успешного добавления интерфейс показывает выбранный товар и количество одной единицы. |
| REQ-CART-03 | Счётчик корзины, строки и итоговая сумма соответствуют фактическому содержимому корзины. |
| REQ-CART-04 | Пользователь может удалить строку из корзины; пустая корзина показывает понятное пустое состояние. |
| REQ-CART-05 | Содержимое корзины сохраняется при переходе между разделами в рамках активного сеанса. |

## 4. Профиль

| ID | Требование |
|---|---|
| REQ-PROF-01 | Профиль показывает имя, электронную почту и телефон тестового пользователя. |
| REQ-PROF-02 | Все три поля доступны для изменения и обязательны для сохранения. |
| REQ-PROF-03 | При корректных значениях операция обновления передаёт актуальные значения всех трёх полей. |
| REQ-PROF-04 | При успешном сохранении интерфейс подтверждает операцию и показывает сохранённые значения. |
| REQ-PROF-05 | Сохранённые значения остаются актуальными после повторного открытия профиля или обновления страницы. |

## 5. Настройки и данные

| ID | Требование |
|---|---|
| REQ-SET-01 | Раздел показывает версию справочника и записи с идентификатором, названием, категорией и статусом. |
| REQ-SET-02 | Фильтр по категории показывает все записи или записи выбранной категории; отсутствие результатов обозначается явно. |
| REQ-SET-03 | Команда публикации увеличивает версию справочника и возвращает подтверждение операции. |
| REQ-SET-04 | После команды обновления пользователь видит актуальную опубликованную версию и записи. |
| REQ-SET-05 | Повторное открытие раздела после публикации показывает актуальное состояние данных. |
| REQ-SET-06 | Действие показа сводки завершает расчёт без необработанных ошибок JavaScript и отображает итог. |
